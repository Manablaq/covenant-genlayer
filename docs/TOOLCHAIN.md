## Dependency lock

Direct dependencies are declared in `requirements-dev.in`:

```text
genlayer-test[sim]==0.29.2
genvm-linter==0.11.0
```

`requirements-lock.txt` is generated by uv with SHA-256 package hashes. Prerelease migrations require an explicit reviewed change.

## GenVM pin

SDK-dependent tooling is pinned to:

```text
GENVM_VERSION=v0.2.16
```

Every production Intelligent Contract must start with:

```python
# { "Depends": "py-genlayer:1jb45aa8ynh2a9c9xn3b7qqh8sm5q93hwfp7jqmwsfhh8jpz09h6" }
# pyright: reportUnknownMemberType=false
```

Runner identity:

```text
py-genlayer:1jb45aa8ynh2a9c9xn3b7qqh8sm5q93hwfp7jqmwsfhh8jpz09h6
```

The exact runner was verified inside the GenVM `v0.2.16` bundle and binds:

```text
py-lib-genlayer-std:11rhn002yfajawsz7fai6mykznbxkxs6l91iskj5cm82c92qhy3v
```

`GENVM_VERSION=v0.2.16` must be supplied explicitly to SDK-dependent linter commands so unrelated cached GenVM artifacts cannot alter validation behavior.

## Required static environment

Run SDK-dependent commands with the project virtual environment on `PATH`:

```bash
PATH="$PWD/.venv/bin:$PATH"
GENVM_VERSION=v0.2.16
```

Required gates:

```text
genvm-lint lint
genvm-lint validate
genvm-lint check
genvm-lint typecheck --strict
genvm-lint schema
```

## Strict-typecheck compatibility rule

The pinned SDK exposes `gl.public.view` with incomplete Pyright typing. Under strict mode this produces `reportUnknownMemberType`.

Covenant suppresses only that rule at file level with the second-line directive shown above. Strict mode remains enabled.

A negative-control probe verified that an intentional `int` assignment to a `str` value is still rejected with `reportAssignmentType`.

The compatibility directive must be removed if a later reviewed SDK/toolchain makes it unnecessary.

## Testing layers

- Direct Mode: deterministic storage/state-machine and unit-level verification.
- GLSim: fast RPC/integration development; not full GenVM consensus proof.
- Full local GenVM/multi-validator runtime: required for consensus-sensitive approval and rejection before Bradbury.
- Bradbury: live verification only after the reviewed backend graph passes predeployment gates.

Raw validator and transaction evidence must be preserved before decoding or summarization.

## Release reproducibility

A backend release records at minimum the git commit/tree, tool versions, hashed dependency lock, GenVM version, runner identity, source hashes, ABI/schema hashes, deployment ordering, constructor arguments, deployed addresses, and deployment/live-verification transaction identities.

Changing the runner, GenVM release pin, dependency lock, or strict-typecheck compatibility rule invalidates affected verification evidence and requires the affected gates to be rerun.
